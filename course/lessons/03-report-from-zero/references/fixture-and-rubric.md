# Контрольные данные и рубрика первого отчёта

## Лист контрольных данных

Подготовь два вымышленных покупателя `AI-SYN-A` и `AI-SYN-B`. В отдельной учебной базе выбери период и четыре **сохранённых** заказа. Точные суммы перепиши из формы после сохранения; фиксированные числа из текста курса не подменяют фактическое состояние Demo83.

| Заказ | Покупатель | Дата относительно периода | Сумма после сохранения | Входит в отчёт |
|---|---|---|---:|---|
| A1 | AI-SYN-A | внутри | | да |
| A2 | AI-SYN-A | внутри | | да |
| B1 | AI-SYN-B | внутри | | да |
| OUT | любой из двух | снаружи | | нет |

Ожидаемые строки: `AI-SYN-A: 2, сумма A1 + A2`; `AI-SYN-B: 1, сумма B1`. Общий итог: `3, сумма A1 + A2 + B1`. Для пустого периода строки отсутствуют. Отдельно проверь заказ в первый и последний день выбранного периода, если можешь подготовить его без изменения других правил.

Если в исходной Demo83 есть другие заказы в том же периоде, выбери изолированный диапазон или дополнительно ограничь контрольный набор подтверждённым признаком. Не объявляй этот лист эталоном для произвольной базы.

## Рубрика

| Уровень | Наблюдаемое свидетельство |
|---|---|
| Недостаточно | Есть только ответ агента или скриншот; источник, fixture либо результат нативного открытия неизвестны |
| Достаточно | Источник и границы периода проверены, diff ограничен отчётом, артефакт открывается, четыре случая совпадают с независимым листом |
| Сильно | Ученик объясняет, почему продажи из регистра не равны заказам, находит риск удвоения строк и показывает, какое изменение данных сделает тест красным |

Отдельно фиксируй `BLOCKED`, если обязательное действие не выполнено: это честный статус проверки, а не оценка способностей ученика.
