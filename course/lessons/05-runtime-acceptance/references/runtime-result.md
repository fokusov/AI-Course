## Что реализовано

В отдельном расширении `AI_Course_Lab`:

- добавлен необязательный реквизит `РасходТовара.Заказ` типа `ДокументСсылка.Заказ`;
- ссылка заполняется после типового `ОбработкаЗаполнения`, если основанием является заказ;
- поле показано в основной форме расхода;
- в проведённом документе поле доступно только для чтения;
- после отмены проведения поле снова становится редактируемым;
- основная конфигурация Demo83 не изменена.

Исходники зафиксированы в `C:\AI-Course-Work\Demo83-Sources`, коммит реализации — `aa94e3a`.

## Найденный нюанс: безопасный режим

Сразу после загрузки ожидаемый эффект обработчиков не наблюдался. После снятия у `AI_Course_Lab` безопасного режима и повторного запуска сценария эффект появился.

Это доказывает последовательность действий и результат на данном стенде, но само по себе не доказывает универсальную причинность: безопасный режим, защита от опасных действий, применимость расширения и обновление конфигурации базы должны диагностироваться раздельно. До отдельного воспроизведения нельзя утверждать, что платформа в общем случае «не вызывает перехватчики в безопасном режиме».

Это важный учебный результат:

1. успешная загрузка и обновление не равны выполнению кода;
2. отсутствие эффекта не доказывает ошибку реализации;
3. перед переписыванием кода нужно проверить активность, применимость и свойства безопасности расширения;
4. отключение защиты допустимо только после проверки источника и состава расширения в отдельном восстанавливаемом контуре;
5. такое решение нельзя механически переносить на рабочую базу или сторонний CFE.

## Семь пройденных сценариев

1. Ввод расхода на основании заказа заполняет ссылку и не дублирует типовое заполнение.
2. После записи и повторного открытия ссылка сохраняется.
3. Ручной расход без заказа записывается с пустой ссылкой.
4. Другие типовые основания не создают случайную ссылку на заказ.
5. После проведения поле видно и доступно только для чтения без переоткрытия.
6. После отмены проведения поле снова редактируется без переоткрытия.
7. Существующий расход открывается без ошибки и имеет пустую ссылку.

## Как использовать в курсе

Пилот становится основой практической цепочки:

```text
исследование исходников
  → спецификация
  → изменение только расширения
  → статическая проверка
  → backup
  → однократная загрузка и обновление
  → проверка свойств применения расширения
  → ручной runtime/UI-пилот
  → принятие или возврат на диагностику
```

Урок не должен заранее подсказывать ученику, что любую проблему решает снятие безопасного режима. Сначала он должен локализовать слой отказа: исходники, загрузка, обновление, применимость, свойства безопасности или прикладная логика.
