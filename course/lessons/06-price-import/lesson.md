# Урок 6. Загружаем прайс-лист через внешнюю обработку

> Результат: внешняя обработка для учебной УНФ показывает план загрузки, затем контролируемо применяет его и даёт понятный результат повторного запуска.

Новый риск — пакетная запись и частичный успех. Цель «регламентный запуск» входит в урок только после проверки поддерживаемого в выбранной версии УНФ и БСП маршрута регистрации внешней обработки и её выполнения по расписанию. Если он не подтверждён, ручной импорт можно принять отдельно, а регламентный этап остаётся `BLOCKED`.

## Контракт до реализации

Используй небольшой синтетический файл с известными строками. Перед кодом определи его формат: разделитель или листы, кодировку, колонки, единицы измерения, валюту, дату цен, ключ сопоставления номенклатуры и действие при отсутствующей позиции. Реши, что делать с дублем, пустой или отрицательной ценой и повторной загрузкой файла. Не угадывай эти правила по примерам агента.

## Две стадии обработки

1. **Предпросмотр без записи.** Обработка читает файл и показывает число строк: к созданию, к обновлению, к пропуску, с ошибкой. Каждая ошибка привязана к номеру строки и правилу; предпросмотр не меняет базу.
2. **Применение.** Только после проверки плана и точки восстановления обработка записывает разрешённые данные. Результат содержит число фактических созданий, обновлений, пропусков и ошибок, идентификатор файла без раскрытия чувствительного пути и состояние после сбоя. Повтор того же файла не должен создавать дубли по согласованному ключу.

Попроси агента разделить чтение файла, проверку строк и запись по существующим контрактам УНФ. Сначала получи preview изменения и план тестов, затем разреши код внешней обработки. Для EPF различай статическую проверку, нативную сборку, round-trip, открытие **точного** SHA-256 артефакта и поведение на данных.

## Проверки

Подготовь небольшой файл: одна новая позиция, одно обновление, один дубль и одна ошибочная строка. До запуска посчитай, сколько строк должно попасть в каждую категорию. Сравни с предпросмотром, затем проверь первый запуск, повтор, испорченную строку и восстановление после неопределённого результата. Для регламентного этапа отдельно проверь фактический запуск, права пользователя задания, результат в журнале и отсутствие повторной бизнес-записи. Наличие расписания в интерфейсе ещё не доказывает выполнение.

Ручной импорт и запуск по расписанию проверяй отдельно. Если второй маршрут не подтверждён на твоей версии УНФ, не считай его готовым только потому, что ручная загрузка работает. Следующий урок добавит взаимодействие с внешней системой по HTTP.
