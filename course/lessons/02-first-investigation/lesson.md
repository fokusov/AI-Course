# Урок 2. Первый результат с Codex и Unica

> Результат: ты нашёл в исходниках два факта о продажах и понял, что пока нельзя проверить без запуска 1С. Проект и база не изменены.

## Подготовка

Выполни [чек-лист установки](../../getting-started/lesson.md). Для первой попытки выбери публичные XML-исходники Demo83. Если после [урока безопасности](../01-safety-and-route/lesson.md) у тебя есть решение `OWN-SOURCES`, можно исследовать разрешённую папку собственного проекта. Не добавляй в workspace базу, `.dt`, журналы, выгрузки, сертификаты и рабочие секреты.

Если ты впервые видишь интерфейс, сначала пройди краткий [практикум Codex](../../quickstarts/codex/lesson.md). [Практикум Unica](../../quickstarts/unica/lesson.md) показывает те же действия через предметные инструменты 1С; в этом уроке достаточно исследовательских операций.

## Задача

Для Demo83 исследуй, откуда формируются продажи для отчёта по покупателям и товарам. Перед обращением к агенту попробуй угадать, какой документ создаёт движения и какие измерения и ресурсы есть у регистра `Продажи`.

Дай Codex одну задачу:

```text
Работай только на чтение в открытом workspace. Не меняй файлы,
не запускай 1С и не обращайся к базе или сети.
Найди документ, который пишет в регистр Продажи, и установи:
1. где находятся движения;
2. какие измерения и ресурсы хранит регистр;
3. какие существующие отчёты используют его обороты.
Для каждого факта приведи путь к исходнику и короткое свидетельство.
Отдельно назови вопросы, для которых потребуется запуск 1С.
```

Попроси Unica показать логические адреса найденных объектов и свойства регистра. Сравни ответ с исходниками. Для исследованной Demo83 1.0.41.3 в регистре подтверждены измерения `Покупатель`, `Товар` и ресурсы `Количество`, `Сумма`; другая версия должна быть проверена заново. Не проси агента писать отчёт, пока не проверил источник данных.

Если работаешь в своём разрешённом проекте, используй ту же структуру вопроса, но названия объектов сначала найди, а не переноси из Demo83. Реальные записи и значения в запрос агенту не копируй.

## Проверка результата

Открой минимум два указанных пути сам: подтверждают ли они вывод агента? Если инструмент сообщил о результате без конкретного источника, попроси показать его. Проверь `git status --short`: после исследования не должно появиться нового diff.

Этого достаточно для перехода к отчёту. Тебе не нужно сдавать карту исследования: важно знать, где лежат исходники и почему ссылка на них надёжнее ответа чата без проекта. [Следующий урок](../03-report-from-zero/lesson.md) начинается с этих же объектов.
