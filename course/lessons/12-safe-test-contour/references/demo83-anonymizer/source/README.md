# AI_АнонимизацияDemo83

Учебная внешняя обработка для Demo83 1.0.41.3. Работать с ней можно только на отдельной учебной копии базы; встроенного отката нет.

## Безопасный canary-пилот

Текущий исполнимый режим затрагивает только восемь синтетических записей с точным маркером `AICANARY`: контрагента, организацию, банк, расчетный счет контрагента, пользователя, входящее письмо, исходящее письмо и хранимый файл. Для справочников с кодом маркер хранится в `Код`, для входящих и исходящих писем — в `Наименование`. Обычные записи Demo83 не выбираются запросами пилота.

1. Установить флаг отдельной копии.
2. Ввести `СОЗДАТЬ CANARY DEMO83` и нажать «Подготовить учебные данные».
3. Убедиться в результате `PASS / CANARY_PREPARED`.
4. Ввести `ОБЕЗЛИЧИТЬ CANARY DEMO83` и нажать «Обезличить canary».
5. Нажать «Проверить результат» и получить `PASS / CANARY_ANONYMIZED`.

Подготовка и обезличивание выполняются каждая в собственной транзакции. Подготовка идемпотентно возвращает canary-записи к исходным синтетическим секретам. Полный прогон через `ВыполнитьСПодтверждениями` всегда возвращает `BLOCKED / FULL_RUN_NOT_RELEASED`.

Для воспроизводимой приемки точного EPF предусмотрен ограниченный rehearsal-вход `/C AI_CANARY_REHEARSAL`. Он выполняет те же три шага только для `AICANARY`, записывает локальный результат в `.build/external-anonymizer/canary-runtime-result.txt` и завершает клиент. Без точного параметра открывается обычная интерактивная форма и автоматических записей нет.

Режим `/C AI_CANARY_VERIFY` ничего не записывает в прикладные объекты: он только проверяет текущее состояние canary, сохраняет тот же evidence-файл и завершает клиент. Оба автоматических сценария стартуют после открытия формы через однократный обработчик ожидания, а исключение сценария также попадает в evidence-файл.

Canary-режим намеренно не очищает историю данных и константы интеграций: такие действия затронули бы штатные данные базы и требуют отдельной приемки. Также вне покрытия остаются документы, регистры, журнал регистрации, резервные копии, `.dt` и внешние файлы.

Перед первым runtime-прогоном должна существовать проверенная резервная копия базы. Статическая валидация, нативная сборка EPF, round-trip, открытие артефакта и поведенческий canary-прогон являются отдельными воротами приемки.
