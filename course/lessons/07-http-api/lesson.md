# Урок 7. HTTP-сервис и клиент стороннего API

> Результат: два маленьких и отдельно проверенных контракта обмена — HTTP-сервис 1С и модуль вызова внешнего API. На занятии они работают с локальным имитатором без действующих ключей.

Новый риск — внешняя граница: запрос может прийти повторно, ответ может потеряться, сеть может зависнуть, а часть действий уже выполниться. Не объединяй оба направления в один большой запрос агенту.

## Часть A. HTTP-сервис в 1С

Сформулируй один безопасный запрос и ответ для чтения синтетического статуса учебного объекта. До кода определись с маршрутом, методом, полями, типами, допустимыми значениями, HTTP-статусами и правами вызова. Исключи персональные данные и запись в базу из первого сценария. Агент исследует существующие HTTP-сервисы выбранной конфигурации как образцы, затем создаёт ограниченный diff. Проверь неверный метод, отсутствующий параметр, несуществующий объект и запрос без разрешённого доступа. Публикация базы наружу не требуется: испытание проводится в изолированном локальном контуре.

## Часть B. Клиент внешнего API

Используй локальный mock с заранее сохранёнными ответами: успех, ошибка формата, `4xx`, `5xx`, таймаут и обрыв после отправки запроса. Сначала опиши адаптер: входные данные, какие поля уходят наружу, авторизация из защищённой настройки, разбор ответа, журнал без секретов и точка, где вызывающий код получает ошибку. Не зашивай токен в модуль, тест или `AGENTS.md`.

Отдельно реши повторы: безопасен ли повтор операции по контракту сервиса, есть ли идентификатор запроса, как проверить состояние после неопределённого ответа. Автоматический повтор мутирующего вызова запрещён, пока идемпотентность не доказана. Сравни структуру запроса/ответа с эталонными сообщениями mock и проверь хотя бы один отрицательный сценарий.

## Приёмка

Для сервиса и клиента отдельно проверь реальный ответ на успех и ошибку; при проверке не выводи секреты в журнал и скриншоты. Статическая диагностика, запуск локального сервиса и проверка внешним тестовым клиентом отвечают на разные вопросы. В конце попробуй объяснить коллеге, какой доступ получил агент, какое решение осталось за тобой и какой тест доказал требование, а не только отсутствие ошибки.
