# Практикум. Первый час с Codex

> Цель: открыть публичные XML-исходники Demo83 в Codex, дать первую задачу по 1С, увидеть действия агента и получить полезный результат без изменения конфигурации.

Это мост между обычным чатом и полноценной агентной разработкой. Мы пока не подключаем базу и не просим написать код. Но Codex уже видит реальный проект, сам ищет файлы и подтверждает выводы ссылками на исходники.

Ориентир по времени: 45–60 минут. Это необязательный практикум для знакомства с инструментом; его можно пропустить, если ты уже уверенно работаешь в Codex.

## Результат

После практикума ученик:

- отличает чат от задачи Codex;
- понимает, что такое workspace и граница папки;
- видит план, действия и итоговый ответ агента;
- умеет задать read-only режим обычным языком;
- проверяет ссылки на исходники;
- знает, где остановить агента и где посмотреть diff;
- видит фактические плагины, skills, MCP, разрешения и настройку памяти, не путая их с возможностями модели.

## Предварительные условия

Выполнен [стартовый чек-лист](../../getting-started/lesson.md). В каталоге:

```text
C:\AI-Course-Work\Demo83-Sources\src\configuration
```

находится локальная выгрузка официальной Demo83. В рабочем каталоге нет клиентского кода, секретов, `.dt` и подключения к информационной базе.

## Шаг 0. Проверяем эффективные возможности

До основной задачи пройди [проверку установки](../../getting-started/codex-basics.md#6-проверь-свою-установку-codex): посмотри на плагины, skills, MCP-серверы, границу workspace и режим подтверждений. Отдельный файл для курса не нужен. Не передавай агенту токены, пароли и полный пользовательский конфиг.

Если память включена, в отдельной безопасной учебной папке можно спросить: «Какие подходы из прошлых 1С-задач могут пригодиться здесь? Отдели воспоминания от фактов текущего проекта». Любой ответ остаётся гипотезой, пока не подтверждён текущими исходниками.

## Шаг 1. Открываем правильную папку

В Codex Desktop открой как проект:

```text
C:\AI-Course-Work\Demo83-Sources
```

Не открывай весь `C:\AI-Course-Work`: там позднее появятся базы и baseline. Граница workspace должна быть уже границы всей лаборатории.

## Шаг 2. Даём первую задачу

Создай новую задачу и передай:

```text
Мы работаем с XML-исходниками официальной Demo83.

Работай только на чтение. Не изменяй и не создавай файлы, не запускай 1С
и не ищи ничего вне открытого проекта.

Найди документы Заказ и РасходТовара. Ответь:
1. может ли РасходТовара создаваться на основании Заказа;
2. какой код при этом заполняет новый документ;
3. сохраняется ли в РасходТовара типизированная ссылка на исходный Заказ.

Для каждого утверждения приведи конкретный относительный путь к исходнику.
Отдели подтверждённые факты от предположений. После ответа остановись.
```

Это уже не «магический промпт». В нём есть задача, границы, ожидаемый формат доказательства и стоп-точка.

## Шаг 3. Наблюдаем, а не ждём вслепую

Пока Codex работает, отметь:

- какие каталоги и файлы он читает;
- использует ли поиск по проекту;
- не пытается ли создать файл или запустить программу;
- сообщает ли о недостатке данных;
- различает ли имя объекта метаданных и физический путь.

Если агент собирается сделать запрещённое действие, отклони его или останови задачу. Остановка — нормальное управление, а не провал.

## Шаг 4. Проверяем ответ

Не оценивай ответ по уверенности и длине. Открой названные файлы и проверь хотя бы два ключевых фрагмента самостоятельно.

Хороший результат должен показать, что:

- `РасходТовара` действительно поддерживает создание на основании `Заказа`;
- существующая обработка заполнения переносит данные заказа;
- отдельная типизированная ссылка на заказ в проверенной версии не сохраняется;
- свободный текст нельзя молча принять за надёжную связь документов.

Если путь не указан или не подтверждает вывод, пометь утверждение как гипотезу и попроси только доказательство этого пункта.

## Шаг 5. Смотрим фактические изменения

В терминале из корня проекта выполни:

```powershell
git status --short
git diff --check
```

Ожидаемый результат: Codex не изменил исходники. Если появились файлы, сначала выясни их происхождение; не удаляй неизвестное состояние автоматически.

## Что сейчас произошло

Обычный чат помогал рассуждать по переданному описанию. Codex получил ещё одну возможность: самостоятельно прочитать разрешённый локальный проект. При этом он не получил сверхспособность понимать бизнес-смысл без вопросов и не получил автоматическое право что-либо менять.

Первый полезный результат агента — не обязательно написанный код. Здесь результатом стало подтверждённое исследование реальной конфигурации.

## Условия завершения

- проверены фактические возможности Codex без передачи секретов;
- открыт только безопасный source-only workspace;
- агент выполнил задачу без изменений;
- ученик проверил минимум два доказательства;
- `git status --short` не показывает неожиданных изменений;
- ученик может объяснить разницу между чатом, агентом, workspace и разрешением;
- ученик отличает память от правил проекта, а plugin — от skill и MCP-инструмента.

Следующий практикум повторит похожую задачу с Unica. Он покажет разницу между «агент умеет читать файлы» и «агент получил предметную модель 1С, логические адреса, специализированные проверки и управляемый путь к будущим изменениям».
