# Подготовка Demo83 для практических уроков

Этот чек-лист выполняется один раз до нативного открытия отчёта или других действий в базе. Для первого read-only исследования Codex достаточно разрешённой XML-выгрузки без подключения базы к workspace.

1. Возьми официальный шаблон `ДемонстрационноеПриложение` закреплённой версии `1.0.41.3` и создай **отдельную файловую базу**. Зафиксируй фактические версии платформы и конфигурации и абсолютный путь. Если версия другая, сначала пересверь исходники и задания.
2. Сохрани исходный `.dt` вне каталога базы и репозитория; запиши размер, дату и путь. Не перезаписывай этот baseline позднейшими опытами.
3. В самой базе инвентаризируй пользователей, контактные данные, почтовые и push-настройки, регламентные задания, ботов, обмены, публикации, внешние файлы и компоненты. Официальное происхождение Demo83 не доказывает, что все настройки безопасны. Не переноси значения секретов в учебные отчёты.
4. Отключи или направь в заведомо фиктивный контур внешние действия, которые могут сработать в упражнении. Неизвестное состояние сетевого механизма — `BLOCKED` для открытия базы агенту и для действий, которые могут его запустить.
5. Выгрузи XML-исходники в отдельный `Demo83-Sources`, проверь, что в папке агента нет `1Cv8.1CD`, `.dt`, настроек подключения и журналов. Зафиксируй Git baseline исходников. Для Unica source-set `demo83` указывает только на XML-исходники.
6. Сохрани новый рабочий baseline базы. Создай один синтетический контрольный объект, восстанови базу из baseline и проверь, что объект исчез, а версии и состав расширений совпали с записанными. Возврат файлов Git не является восстановлением базы.
7. Перед каждым следующим нативным действием повторно проверь точный путь базы, состояние Git и пригодную точку восстановления.

В [инвентаризации закреплённого релиза](../lessons/02-demo83-lab/references/demo83-inventory.md) есть пример классов рисков. Она отражает один исследованный экземпляр и не заменяет проверку твоей базы. Подробные команды прежней версии курса доступны в истории репозитория; этот чек-лист — действующая короткая входная точка.

## Минимальный паспорт

```text
Источник шаблона и версия:
Путь базы и XML-исходников:
Версия платформы:
Исходный и рабочий baseline:
Какие внешние действия проверены и отключены:
Как доказано восстановление:
Что остаётся неизвестным:
Решение для текущей задачи: READY / BLOCKED
```

Если результат `BLOCKED`, продолжай теорию и read-only исследование исходников; к runtime возвращайся после устранения точной причины.
