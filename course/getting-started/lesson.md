# Что поставить, чтобы начать курс

> Короткий ответ: для первых практических уроков нужны Codex Desktop, Git, PowerShell 7, платформа 1С совместимой версии, официальная Demo83 и плагин Unica. Это позволяет исследовать локальные исходники, предлагать изменения и проверять diff. Учебная УНФ понадобится позже для соответствующих уроков.

Актуальная последовательность занятий находится в [маршруте курса](../index.md). Урок 0 можно пройти до установки; этот документ нужен перед уроком 1 и ускоренными практикумами.

Этот документ — техническая точка входа. Он отвечает на естественный вопрос опытного разработчика: «что поставить на компьютер, чтобы попробовать агентную разработку уже сегодня?» Безопасность при этом не откладывается на потом: первые задания выполняются только на публичной Demo83 и сначала только по XML-исходникам.

## Наш основной учебный стек

| Слой | Что используем | Зачем |
|---|---|---|
| Интерфейс агента | Codex Desktop | Открыть локальный проект, дать задачу, наблюдать действия, принимать или запрещать изменения |
| Командная строка | Codex CLI | Установить и проверить плагины; в основном уроке почти не нужна |
| История изменений | Git for Windows | Увидеть фактический diff и безопасно отделить работу агента от исходного состояния |
| Терминал | PowerShell 7 | Выполнять воспроизводимые команды курса |
| Учебная конфигурация | Официальная Demo83 | Работать с настоящими объектами платформы без клиентских данных и архитектуры большой типовой конфигурации |
| 1С-инструменты агента | Unica | Дать Codex предметную модель проекта 1С: адресно исследовать, изменять и проверять метаданные и BSL, а позже управляемо переходить от исходников к платформе |

Codex — основной агент курса, а Codex Desktop — основной интерфейс. Это не означает, что методика работает только с ним. В начале нужен один общий интерфейс, чтобы ученик изучал инженерный процесс, а не одновременно сравнивал пять агентов.

## Что пока не требуется

На старте не устанавливай специально ради курса:

- OpenCode или Pi;
- BSL Flow и управляемый многостадийный процесс;
- WSL и Docker;
- несколько наборов 1С-skills одновременно;
- YAxUnit и Vanessa Automation;
- сложную маршрутизацию моделей;
- доступ агента к рабочей базе или рабочему репозиторию.

OpenCode, Pi и BSL Flow появятся в продвинутом продолжении. Сначала ученик должен вручную пройти и понять один полный цикл с Codex + Unica. Тестовые фреймворки подключим тогда, когда дойдём до соответствующего слоя доказательств.

## Семь понятий до первой задачи

| Понятие | Простое объяснение |
|---|---|
| Модель | Нейросеть, которая рассуждает и формирует ответ |
| Чат | Диалог, в котором модель видит только переданный ей контекст |
| Агент | Модель с рабочим окружением и инструментами: она может читать файлы, запускать разрешённые команды и готовить изменения |
| Skill | Инструкция для повторяемого типа работы: например, исследование BSL-кода или анализ метаданных |
| MCP-инструмент | Конкретная типизированная операция, которую агент вызывает из skill: поиск, чтение объекта, валидация и так далее |
| Плагин | Устанавливаемый пакет, который объединяет связанные skills, MCP-серверы и другие расширения |
| Память Codex | Вспомогательный межпроектный контекст из прошлой работы; полезен для поиска знакомых подходов, но не заменяет проверку фактов и проектные правила |

`AGENTS.md` — это постоянные инструкции для агента: глобальный файл хранит твои устойчивые личные соглашения, а проектный — версионируемые правила конкретного репозитория. Их устройство и практическая проверка разобраны в [материале про AGENTS.md](agents-md.md). Папка, открытая в Codex, задаёт workspace и важную границу доступа. Перед установкой Unica также пройди [ликбез по возможностям и настройкам Codex](codex-basics.md): он показывает, где проверять плагины, skills, MCP, разрешения и память.

## Почему Codex недостаточно без Unica

Codex уже умеет читать файлы, искать текст, редактировать код, запускать разрешённые команды и показывать diff. Для обычного проекта этого часто достаточно. Но выгрузка 1С — не просто набор XML и BSL-файлов:

- один прикладной объект разложен по нескольким файлам и каталогам;
- физический путь не равен смыслу объекта;
- ручная правка XML легко нарушает состав, ссылки или формат выгрузки;
- формы, роли, СКД, макеты и расширения имеют разные внутренние контракты;
- статически корректный файл ещё не означает, что конфигурация загрузится и правильно поведёт себя в базе;
- безопасный переход от исходников к информационной базе требует отдельного управляемого процесса.

Без Unica Codex видит эту структуру прежде всего как текст. Он может разобраться, но вынужден каждый раз заново восстанавливать устройство выгрузки, угадывать связи между файлами и собирать команды платформы. Результат сильнее зависит от конкретного промпта и хуже воспроизводится.

Unica добавляет недостающий предметный слой. Для агента появляются:

- **source-set** — именованный набор исходников конфигурации или расширения;
- **логические адреса** наподобие `demo83:Document.РасходТовара`, не зависящие от раскладки файлов;
- типизированные операции поиска, чтения, сравнения, изменения и проверки;
- 1С-skills с готовыми рабочими маршрутами для метаданных, форм, ролей, СКД, BSL, расширений, интеграций и других областей;
- документация платформы и стандартов как отдельный проверяемый источник;
- `v8-runner` как нижний runtime-слой для операций, где уже нужна установленная платформа и информационная база.

Поэтому фраза «без Unica не обойтись» в рамках курса означает не «Codex физически не способен изменить XML». Она означает: мы не считаем случайную текстовую правку достаточным инженерным процессом для 1С. Наш стандарт — предметная адресация, план до записи, ограниченный diff, специализированная проверка и отдельный контролируемый переход к runtime.

## Как устроена связка Codex + Unica

```text
задача разработчика
        ↓
Codex: понимает цель, исследует контекст, строит план и ведёт диалог
        ↓
skill Unica: задаёт проверенный маршрут конкретной 1С-задачи
        ↓
MCP-инструменты Unica: находят, читают, сравнивают, меняют и проверяют
        ↓
XML-исходники под Git
        ↓ только после отдельного разрешения и safety-gate
v8-runner → платформа 1С → учебная информационная база
```

Роли здесь не смешиваются:

- **Codex** оркестрирует работу и общается с разработчиком;
- **skill** объясняет агенту, как проходить конкретный класс 1С-задач;
- **Unica** предоставляет типизированные предметные операции;
- **v8-runner** приводит разные способы запуска платформы к воспроизводимым операциям над исходниками, артефактами и базой;
- **Git и человек** остаются внешней границей контроля и приёмки.

Обычно разработчик формулирует задачу человеческим языком. Codex сам подбирает skills и инструменты. Явные имена `$unica:...` мы используем в первых уроках только затем, чтобы ученик увидел механику и научился проверять выбранный маршрут.

## Порядок установки

### 1. Codex Desktop и Codex CLI

Установи Codex и войди в свою учётную запись. Актуальную процедуру бери из [официального quickstart Codex](https://developers.openai.com/codex/quickstart): интерфейс и дистрибутив могут изменяться быстрее курса.

Проверь CLI в PowerShell:

```powershell
codex --version
```

До подключения 1С-инструментов выполни инвентаризацию из [ликбеза по Codex](codex-basics.md) и сохрани `Evidence\Setup\codex-capabilities.md`. Это отделит возможности самого Codex от того, что позднее добавит Unica.

Если Desktop работает, а команда `codex` не найдена, не переходи к установке Unica: сначала закончи установку CLI и открой новый терминал.

### 2. Git и PowerShell 7

Если инструментов ещё нет, используй официальные страницы [Git for Windows](https://git-scm.com/download/win) и [установки PowerShell на Windows](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows). После установки открой новый терминал.

Проверь:

```powershell
git --version
pwsh --version
```

Версия Git здесь не является учебной целью. Нам нужны рабочие команды `status`, `diff` и локальная история. Все команды курса рассчитаны на PowerShell 7, а не на старый Windows PowerShell 5.1.

### 3. Платформа 1С и Demo83

Для исследованного контура закреплена официальная демонстрационная конфигурация «Управляемое приложение» (`ДемонстрационноеПриложение` 1.0.41.3). У неё подтверждён режим совместимости `8.3.27`, но это не доказывает минимальную подходящую версию платформы для всех практик. Официальные демонстрационные конфигурации публикуются фирмой 1С на [странице Demo83](https://v8.1c.ru/podderzhka-i-obuchenie/demonstratsionnye-konfiguratsii/) и в составе поставок платформы. Перед runtime-пилотом зафиксируй фактическую версию платформы и конфигурации; рабочие базы к агенту не подключай.

Если официальный источник предлагает уже другой релиз или другое имя конфигурации, не подменяй им `1.0.41.3` молча. Зафиксируй найденную версию и остановись со статусом `BLOCKED` до пересверки inventory и практических заданий курса.

Создай корневой каталог лаборатории:

```powershell
New-Item -ItemType Directory -Force -Path C:\AI-Course-Work
```

Короткий действующий сценарий создания базы, baseline и восстановления находится в [чек-листе Demo83](demo83-lab.md). Для первого read-only исследования достаточно разрешённых XML-исходников в:

```text
C:\AI-Course-Work\Demo83-Sources\src\configuration
```

На этом раннем маршруте Codex открывает только `Demo83-Sources`. Путь к информационной базе ему не передаётся. Это специальное исключение для публичной учебной конфигурации, а не разрешение повторять эксперимент на рабочем коде.

Создай локальный Git baseline исходников:

```powershell
Set-Location C:\AI-Course-Work\Demo83-Sources
git init
git add .
git commit -m "Baseline official Demo83 sources"
git status --short
```

Последняя команда не должна выводить файлов. Если Git просит настроить имя и email автора, настрой их осознанно и повтори только `git commit`: не копируй чужие учебные значения в свою глобальную конфигурацию. Перед первым runtime этот baseline будет проверен и включён в паспорт лаборатории.

### 4. Unica

Unica — основной набор 1С-skills и инструментов курса. Актуальное описание, поддерживаемые версии и установка находятся на [официальном сайте Unica](https://ingvarconsulting.github.io/unica/). Каталог реальных задач вынесен на страницу [«Что умеет Unica»](https://ingvarconsulting.github.io/unica/scenarios.html): он строится из приёмочных сценариев проекта, а не из списка будущих пожеланий.

Проверено 21 сентября 2026 года: публичная версия — `0.12.3`. Она поддерживает выгрузки платформы `8.3.27.x` в формате `2.20`. Версии `8.3.26.x` и ниже не поддерживаются намеренно, а поддержка форматов 8.5 заявлена как будущая. Поэтому учебный стенд закреплён на 1С 8.3.27.x. Если на официальном сайте уже опубликована следующая версия, используй её только после проверки учебного сценария преподавателем.

Для установки нужны Git и Codex. Отдельно устанавливать Node.js, Python или Rust для публичной версии не требуется. Выполни команды:

```powershell
codex plugin marketplace add IngvarConsulting/unica-marketplace --ref main
codex plugin add unica@unica
codex plugin list
```

При первом запуске Unica докачивает закреплённое runtime-ядро и внутренние движки из GitHub Releases и проверяет их SHA-256. Поэтому первая новая задача может открывать инструменты дольше последующих. Исходники проекта при этом обрабатываются локально; с моделью общается Codex. Сетевой поиск по базе знаний и стандартам — отдельная возможность, правила которой нужно перепроверять для установленной версии перед работой в корпоративном контуре. В базовом курсе мы не передаём туда закрытые данные.

После установки открой новую задачу Codex или перезагрузи плагины. Для курса новая задача предпочтительнее: список skills и MCP-инструментов точно собирается заново.

Попроси агента выполнить только проверку:

```text
Проверь, что плагин Unica подключён в этой задаче.
Перечисли доступные группы 1С-skills и MCP-инструментов.
Ничего не устанавливай, не изменяй и не запускай.
```

Не сравнивай результат с заученным числом skills: набор развивается. Важно увидеть пространство имён `unica`, специализированные 1С-skills и отсутствие ошибок запуска плагина.

### Что становится доступно после установки

| Возможность | Что получает разработчик |
|---|---|
| Навигация по конфигурации | Поиск и чтение объектов по смыслу и логическому адресу, а не только по имени файла |
| Работа с BSL | Поиск объявлений и вызовов, адресное чтение и контролируемые изменения методов |
| Метаданные | Создание и изменение объектов, реквизитов, табличных частей, форм, ролей, подсистем и расширений через специализированные контракты |
| Сложные форматы | Отдельные инструменты для форм, СКД, MXL, ролей, XDTO и других структур, которые опасно править как произвольный XML |
| Проверки | Типизированная валидация объекта, диагностика BSL, структурный diff и проверка готовности workspace |
| 1С-знания | Skills по проведению документов, регистрам, блокировкам, размещению кода, интеграциям, производительности и безопасности |
| Runtime-маршрут | Через встроенный `v8-runner`: планирование загрузки и выгрузки, сборки CF/CFE/EPF/ERF, запуска клиента и тестовых инструментов |

Это карта возможностей, а не разрешение сразу использовать их все. В базовом курсе доступ раскрывается слоями: сначала чтение, затем preview изменений, затем запись в Git-исходники и только после отдельной подготовки — действия с учебной базой.

### Где здесь v8-runner

[`v8-runner`](https://ingvarconsulting.github.io/v8-runner-rust/index.html) — отдельный исполняемый компонент, который приводит ручные действия Конфигуратора, `ibcmd` и других интерфейсов к единому проектному словарю. В целевой модели он умеет работать с XML и EDT, конфигурациями, расширениями, внешними обработками и отчётами, файловыми и серверными базами, сборкой, загрузкой, выгрузкой, запуском и тестами.

Важно: сайт `v8-runner` описывает целевое состояние, и не каждая показанная там команда уже доступна в публичной версии Unica. Ученик не вызывает внутренний runner напрямую и не копирует команды с сайта вслепую. Codex использует поддержанный skill `$unica:v8-runner`, получает preview допустимой операции и явно показывает границу между планом и фактическим запуском.

В корне `Demo83-Sources` создай `v8project.yaml`:

```yaml
format: DESIGNER
builder: DESIGNER
source-set:
  - name: demo83
    type: CONFIGURATION
    path: src/configuration
```

Этот файл описывает только набор исходников. В нём намеренно нет подключения к базе, логина и пароля. Runtime-настройки появятся позже в локальном, не публикуемом контуре.

Файл `v8project.yaml` нужен не только будущему запуску 1С. Уже на source-only этапе он сообщает Unica, что каталог `src/configuration` — это конфигурация с именем `demo83`. Благодаря этому запрос разработчика обращается к `demo83:Document.РасходТовара`, а физические XML- и BSL-файлы Unica разрешает сама.

### Обновление Unica

Перед очным потоком преподаватель обновляет и повторно проверяет стенд. Ученик не обязан обновляться посреди прохождения курса без причины.

```powershell
codex plugin marketplace upgrade unica
codex plugin remove unica@unica
codex plugin add unica@unica
```

После обновления открой новую задачу Codex. Обновление инструмента не отменяет проверку версии курса: новые возможности могут появиться, а контракты и поддерживаемые форматы — измениться.

## Почему не ставим Unica и cc-1c-skills вместе

Оба проекта решают близкую задачу: дают агенту специализированные навыки работы с 1С. Если новичок одновременно подключит два больших перекрывающихся набора, ему будет трудно понять, почему агент выбрал конкретный skill и какой контракт сейчас действует.

Поэтому базовый маршрут курса один:

```text
Codex Desktop + Unica
```

[`cc-1c-skills`](https://github.com/Nikolay-Shirokov/cc-1c-skills) будет описан в отдельном приложении как альтернативный набор и как упражнение на перенос методики. Это не оценка «лучше — хуже», а способ сохранить один воспроизводимый учебный стенд.

## Самопроверка готовности

К первому уроку с агентом ты готов, если:

- Codex Desktop открывается и может открыть выбранную папку;
- команды `codex`, `git` и `pwsh` доступны;
- установлена локальная Demo83 без клиентских данных;
- XML-исходники находятся строго внутри `Demo83-Sources\src\configuration`;
- `v8project.yaml` не содержит подключения и учётных данных;
- `codex plugin list` показывает Unica;
- после установки Unica создана новая задача Codex;
- Codex видит специализированные 1С-skills и инструменты Unica без ошибки запуска;
- сохранён `Evidence\Setup\codex-capabilities.md` с фактическими настройками без секретов;
- создан и проверен маленький проектный `AGENTS.md`, а глобальные правила отделены от проектных;
- ты можешь объяснить роли плагина, skill, MCP, Unica и `v8-runner` в одном рабочем цикле;
